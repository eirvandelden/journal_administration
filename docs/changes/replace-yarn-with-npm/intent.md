# Intent: Replace yarn with npm in personal projects

Author: Etienne van Delden de la Haije. Status: accepted. Type: chore. Delivery: autonomous

## Problem

Yarn was the preferred Node package manager. It no longer is: npm is the standard. The playbook rule "Node: use yarn, not npm" and eight personal repos still say yarn. Two package managers in one toolchain cause drift between lockfiles, CI, docs and git hooks.

## Proposed outcome

Every personal repo that uses yarn uses npm instead. No `yarn.lock`, `bin/yarn`, yarn command, yarn CI step or yarn guidance remains in them. The dotfiles tell agents to use npm.

## Affected users and systems

- Etienne and agents working in these repos.
- Repos with a `yarn.lock`: cityofbrass, clocky, ddicompendium, dm-adventure-book, happiness, journal_administration, mvpa.css, sticker-app.
- appkit (yarn calls in the shared `lefthook.yml`, no lockfile).
- dotfiles: the `dependencies` skill rule and any other yarn guidance Etienne owns.
- GitHub Actions CI and the cityofbrass Dockerfile.

## Constraints

- Each repo ships as its own pull request, delivered autonomously (playbook §7a). Etienne approves the merges.
- Approved now: editing `.github/workflows/ci.yml` in all repos and the cityofbrass `Dockerfile` (playbook rule 13). No deploy commands.
- No dependency is added or removed. npm resolves the same packages; `package-lock.json` replaces `yarn.lock`.
- No system tooling change (rule 8). npm must already be available; a missing runtime is a stop-and-ask.
- Never add a skipped test or linter disable comment to pass (rule 14, §7a).
- Dotfiles is public: no work references in its diff.

## In scope

- Replace `yarn.lock` with `package-lock.json`, generated by `npm install` in each of the eight repos.
- Replace yarn commands with npm equivalents in CI workflows, the cityofbrass Dockerfile, `bin/setup`, `bin/update`, `config/ci.rb`, lefthook files, AGENTS.md and README.
- Switch CI `cache: yarn` to `cache: npm` and `--frozen-lockfile` to `npm ci`.
- Remove `bin/yarn` and yarn-only settings (`check_yarn_integrity`, yarn ignore entries) where nothing else needs them.
- Update tests that assert yarn commands (cityofbrass `setup_test.rb`, mvpa.css `continuous_integration_test.rb`).
- appkit `lefthook.yml`: yarn calls become npm calls.
- Dotfiles `dependencies` skill: "Node: use yarn, not npm" becomes npm.

## Out of scope

- Work repos (nedap/*, dotfiles-work): they keep yarn.
- The qmk_firmware fork and other upstream forks.
- Third-party reference text, such as the vendored Rails guides.
- Upgrading Node or any package version.
- Adding or removing dependencies.

## Acceptance criteria

- Installing in a migrated repo with `npm ci` succeeds and uses `package-lock.json`.
- A migrated repo has no `yarn.lock` and no `bin/yarn`.
- A migrated repo's CI runs `npm ci` and its lint and test scripts with npm, and CI is green.
- Running `bin/setup` in a migrated Rails repo installs JavaScript packages with npm.
- The repo's tests and linters pass as before the change.
- A search of a migrated repo for `yarn` (excluding fixtures and data) finds nothing.
- The dotfiles `dependencies` skill says to use npm, not yarn.
